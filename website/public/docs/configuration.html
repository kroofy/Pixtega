Configuration

Pixtega is configured with a single TOML document. The schema is closed: an unknown field stops startup, as does any invalid value. There are no silent defaults for limits — what you configure is what runs.

Where configuration comes from

The service checks three places, in this order, and uses the first match:

  1. CLI argument — a TOML file path passed as the first argument: image-service /path/to/config.toml
  2. CONFIG_FILE — an environment variable holding a TOML file path.
  3. CONFIG — an environment variable holding the full TOML document inline. Useful where mounting files is awkward, such as AWS Lambda.

If none is provided, startup fails with no configuration: pass a TOML path, or set CONFIG_FILE or CONFIG. Relative paths inside a config file (filesystem roots, CA certificate files) resolve against the file's directory; with inline CONFIG, they resolve against the process working directory.

Annotated overview

This mirrors config.example.toml from the repository. 

# Where to listen.
listen_address = "0.0.0.0:8080"
# URL prefix for the image contract; requests outside it are rejected.
path_prefix = "/images"

# The closed Width Allowlist. Callers may only request these widths.
allowed_widths = [320, 640, 1280, 1920]

# Source size cap (bytes), enforced on the advertised length and again
# while streaming.
max_download_bytes = 52428800
# Decode-bomb guard, checked from header metadata before decoding.
max_source_megapixels = 100
# One timeout over the whole source exchange.
download_timeout_ms = 10000
# HTTP(S) redirect bound (same origin, same base path only).
max_redirects = 3
# Process-wide fetch+process permits.
max_concurrent_derivations = 8
# Cache lifetime of 200 responses without a `v` token.
unversioned_success_ttl_seconds = 3600
# Cache lifetime of 404 responses.
not_found_ttl_seconds = 60

# One block per enabled output format. `default_quality` is required.
# An empty or absent `allowed_qualities` means callers cannot pass `q`
# for that format at all.
[formats.webp]
default_quality = 82
allowed_qualities = [60, 72, 90]

[formats.avif]
default_quality = 55
allowed_qualities = [40, 65]

[formats.jpeg]
default_quality = 85
allowed_qualities = [70, 92]

# Each source maps a mount name to a backend. Callers can never supply
# a hostname, bucket, directory, or transport — only the mount.
[[sources]]
mount = "public"          # [a-z][a-z0-9-]{0,31}, unique
key_prefix = "media"      # omitted => defaults to the mount; "" => none
transport = "http"        # or "filesystem" or "s3"
base_url = "https://images.example.test"

[[sources]]
mount = "fixtures"
key_prefix = ""
transport = "filesystem"
root = "./fixtures"       # resolved relative to the config file

[[sources]]
mount = "archive"
key_prefix = "originals"
transport = "s3"
bucket = "example-image-bucket"
region = "us-east-1"

Source transports

http

Requires base_url (http or https). An optional ca_certificate_file (PEM, HTTPS only, resolved relative to the config file) supports local fixture servers; hostname verification always stays on. Use HTTPS outside loopback and trusted private networks.

filesystem

Requires root, resolved relative to the config file and canonicalized at startup. Symlinks below the root are always rejected.

s3

Requires bucket and region; optional endpoint_url and force_path_style support local S3-compatible servers.

S3 credentials and permissions

Credentials are never read from TOML. The adapter uses the standard AWS SDK credential provider chain: environment variables (AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY), shared config/credentials files and profiles, and instance/task roles.

The service needs s3:GetObject on the configured prefix. With GetObject permission alone, S3 answers a missing key with 403 instead of 404 unless the principal also has s3:ListBucket; without list permission every missing object is reported (correctly, per the error taxonomy) as 502 source-unavailable rather than 404. Grant s3:ListBucket on the bucket if you want missing keys to become cacheable 404s.

Every validation rule is specified in SPEC.md. When in doubt, the spec and the startup error messages are authoritative.
