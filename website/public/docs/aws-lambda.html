Deploy on AWS Lambda

The recommended serverless path: a Lambda container image built from Dockerfile.lambda, fronted by a Function URL. The image is the standard container plus the AWS Lambda Web Adapter extension, which translates Lambda invocations into plain HTTP — the binary contains no Lambda-specific code and the same image runs on ECS, EC2, or locally.

How it fits together#

  • Dockerfile.lambda adds the Lambda Web Adapter as a Lambda extension and clears the default command, so configuration comes from the environment instead of a baked-in file.
  • Inline configuration. The service reads its full TOML configuration from the CONFIG environment variable when no file is given (see Configuration), so config changes are a Lambda environment update, never an image rebuild. Keep listen_address = "0.0.0.0:8080" — the adapter forwards to port 8080 by default.
  • TCP readiness. The image sets AWS_LWA_READINESS_CHECK_PROTOCOL=tcp because the service has no HTTP health endpoint (GET / is a 400 by design); the adapter waits for the TCP socket instead of an HTTP 200.
  • Response streaming by default. The image sets AWS_LWA_INVOKE_MODE=response_stream, so create the Function URL with --invoke-mode RESPONSE_STREAM to match. If the two disagree, responses come back as the adapter's buffered JSON envelope instead of image bytes. ALB and API Gateway do not support Lambda response streaming — behind those triggers, override the function environment to AWS_LWA_INVOKE_MODE=buffered.
  • S3 sources use the execution role. Credentials are never read from TOML; grant the function's role s3:GetObject on the configured prefix (and ideally s3:ListBucket so missing keys become cacheable 404s instead of 502s).

Deployment outline#

# 1. Build the Lambda image
docker build -f Dockerfile.lambda --platform linux/amd64 -t pixtega-lambda .

# 2. Push to ECR
docker tag pixtega-lambda "$ECR_REPO:latest"
docker push "$ECR_REPO:latest"

# 3. Create the function with inline TOML configuration
aws lambda create-function \
  --function-name pixtega \
  --package-type Image \
  --code ImageUri="$ECR_REPO:latest" \
  --role "$ROLE_ARN" \
  --memory-size 1024 --timeout 30 \
  --environment "Variables={CONFIG=$(cat deploy/lambda/example-config.toml)}"

# 4. Expose a Function URL for a smoke test (dev only — see below)
aws lambda create-function-url-config --function-name pixtega \
  --auth-type NONE --invoke-mode RESPONSE_STREAM
curl -o out.webp "${FUNCTION_URL}images/fixtures/photos/example.jpg/w640.webp"

The complete walkthrough — ECR login, IAM policies, permissions for the public URL, and the smoke test — lives in the repository at deploy/lambda/README.md, with a ready-made example-config.toml.

Production exposure#

--auth-type NONE makes the Function URL publicly invokable by anyone, with no cache absorbing traffic and no auth layer — it is for the smoke test above only, not for an internet-facing production endpoint. For production, put CloudFront in front (the service's cache policy is designed for it), switch the Function URL to --auth-type AWS_IAM with a CloudFront Origin Access Control (OAC) for Lambda Function URLs so only the distribution can invoke the function, and remove the public NONE invoke permission. Details in deploy/lambda/README.md.

Caveats#

  • 6 MB response limit. Buffered Function URL responses are capped at about 6 MB, so the image and this guide default to response streaming (AWS_LWA_INVOKE_MODE=response_stream in the image plus --invoke-mode RESPONSE_STREAM on the Function URL), which raises the limit substantially. The two must stay in sync. To run buffered instead, set the Function URL to BUFFERED and AWS_LWA_INVOKE_MODE=buffered on the function, and consider constraining allowed_widths and allowed_qualities so oversized outputs cannot be produced.
  • Cold starts. Each new execution environment loads libvips, validates configuration, and verifies every enabled encoder, so the first request is noticeably slower than warm ones. A CDN in front absorbs most of this — the service's cache policy is designed for exactly that.
  • Environment size. Lambda caps the function environment at 4 KB total. If your TOML does not fit in CONFIG, bake a config file into the image and point CONFIG_FILE at it.
Prefer a plain container platform? The standard Dockerfile image works unchanged on ECS, Fargate, or any Docker host — see Getting started.
