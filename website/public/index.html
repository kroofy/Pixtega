Any size. Any format. One original.

Pixtega resizes and re-encodes images when they're requested. WebP, AVIF, JPEG. It returns bytes a CDN can cache hard. Keep the original. Pixtega builds the sizes you allow. No asset-pipeline ritual.

Get started View on GitHub

One URL per image

GET /images/public/photos/example.jpg/w1280.webp?v=7d91c2

The mount (public) picks a configured source. The path names the original. The last segment is the size and format: w{width}[,q{quality}].{format}. Widths and qualities come from allowlists. See the API reference for the full grammar. An optional v query param is for cache busting when the original changes.

Why Pixtega

  • Keep the original. You store one file. When a size is requested, Pixtega builds it. No export script. No folder of thumbnails to keep in sync.
  • You allow the sizes. Widths, formats, and qualities are allowlists in the config. A caller cannot invent a 10,000px request. The service never upscales.
  • One URL per image. Same original, same size, same format: same path. Put it on a page and leave it.
  • Built to sit behind a CDN. Successes come back with Cache-Control a CDN can honor. Errors are no-store, so a failed request does not poison the cache.
  • Sources stay behind mount names. HTTP, the filesystem, or S3. Callers see a mount name. Never a hostname, a bucket, or a directory.
  • Honest errors. Quiet logs. Permission denied is a 502, not a cacheable 404. One structured JSON line per request. Credentials stay out of the log.
  • Small to run. One Rust binary or a Lambda image. TOML config. Encoders are checked at startup, so a missing format fails the deploy instead of the request.

Output formats

WebP, AVIF, and JPEG, each with its own default quality and quality allowlist. Encoding uses libvips. Every enabled encoder is checked at startup. A deploy missing an encoder fails then, not when the first request asks for that format.

The Rust crate and binary are also named pixtega. URL grammar, caching, and errors are in the API reference and the README.
