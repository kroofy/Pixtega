Derive images on demand. Cache them forever.

Pixtega is an open-source image derivation service written in Rust. It fetches a source image from a configured backend — HTTP(S), the local filesystem, or S3 — resizes and re-encodes it to a bounded variant, and returns cacheable image bytes. Every derived image has exactly one URL.

One URL, one derived image

GET /images/public/photos/example.jpg/w1280.webp?v=7d91c2

The mount (public) selects a configured source backend, the path names the original, and the final segment is the transform: w{width}[,q{quality}].{format}. Widths and qualities come from closed allowlists, spelling out a default quality is rejected, and the optional v token unlocks year-long immutable caching. See the API reference for the full grammar.

Why Pixtega

  • Bounded by design Widths, formats, and qualities are closed allowlists in configuration. Callers can never request an unbounded transform, and the service never upscales a source image.
  • Three source transports HTTP(S) origins, local filesystem roots, and S3 buckets — including S3-compatible servers via a custom endpoint. Callers never see a hostname, bucket, or directory, only a mount name.
  • Cache-first responses Versioned successes are served with public, max-age=31536000, immutable; unversioned successes and 404s get configurable TTLs; every other error is no-store. Built to sit behind a CDN.
  • Strict input validation Paths are decoded exactly once and strictly validated: no traversal, no encoded delimiters, canonical percent-encoding only. Symlinks below a filesystem root are always rejected.
  • Abuse limits built in A source download size cap, a megapixel decode-bomb guard, a single timeout over the whole source exchange, a redirect bound, and a process-wide concurrency limit — all configurable, all with hard ranges.
  • Honest errors, structured logs A precise error taxonomy (permission denied is 502, never a cacheable 404) and exactly one structured JSON completion event per request, with a stable outcome from a closed set. Credentials and version tokens are never logged.

Output formats

WebP, AVIF, and JPEG, each with its own default quality and quality allowlist. Encoding is done with libvips, and every enabled encoder is verified at startup — a deployment missing an encoder fails fast instead of serving partial formats.

The Rust crate and binary are also named pixtega. The full behavioral contract — URL grammar, caching, errors — is documented in the API reference and the README.
